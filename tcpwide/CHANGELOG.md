## 1.0.1 — 2026-08-27

**1.0.0 除版本号外与 0.30.0 逐字节相同**，本版把这件事变成可验证的，
并修掉两个挡在验证路上的 bug。

- 回退 1.0.0 在 `render_panel` 里的两行显示改动。现在
  `git diff <0.30.0> HEAD -- tcpwide/tcpwide.sh` 只剩 `VERSION` 那一行
- **跨地区表按配置分组，不再按版本号。** `config_fingerprint` 以
  `tcpwide <版本> ｜` 开头，而表是按整个指纹分组的——版本号一变，
  同一套配置的历史就被劈成两组，永远不同行对比。
  0.30.0 和 1.0.0 的 apply 产出逐字节相同，样本却进不了同一行。
  **那张表本来就是为「这次改动有没有帮助」建的，被自己的版本号挡住了。**
  分组时剥掉版本前缀，已存的记录一并归位，不用改数据
- **重跑 install 不再静默改配置。** 覆盖 RTT 的默认值原来取实时测量，
  测不到就用常量 250——配了 180 的人升级时回车就变成 250，且没有任何提示。
  档位同理，默认来自机器推导而不是已存配置。现在每一项默认值都是当前设置，
  实测结果作为建议另行显示

**调参默认值一个没动**：1.0.0 锁死的 17 个 sysctl 键、四个档位预设全部不变。

## 1.0.0 — 2026-08-27

**调参阶段结束，转推广版本。** 单线程实测（洛杉矶 → 上海电信 133ms）：
平均 1.08 Gbps / 峰值 1.40 Gbps。

- **调参默认值冻结**，并由自测逐项锁死：四个档位的预设组合、
  不整形档写出的全部 17 个 sysctl 键值和方向、四个档位的队列规格。
  改任何一个默认值都会让自测变红
- 新增 [TUNING.md](./TUNING.md)：每个键的值、推导、证据，
  以及**明确不做的事**（BBRv3、`netdev_budget`、policer 扫描、单流限速……）
- README 从 1671 行压到 159 行；过程记录搬到 DECISIONS.md，一行没删
- 版本号只剩一处真源（README 曾写着 0.29.1 而代码是 0.30.0）
- 面板：无记录时显示「按 8 记录」而不是 `-`；`notsent_lowat=0` 显示
  「系统默认」而不是裸的 `0`

## 0.23 – 0.30 — 诊断能力

- **0.30.0** 跨地区对比表（`t`）：按配置 × 地区聚合，给出跨地区中位和最差地区。
  `8` 自动记录，地区按对端 IP 自动识别。两段腿按秒对齐，
  判定掉速是上游供给不足还是本机侧
- **0.29.1** 撤回没有 A/B/A 支撑的首窗改动（64 → 32 让四个地区全掉到 35–113 Mbps）
- **0.28.0** 高速档暖启动：`initcwnd/initrwnd 64` + 缓冲起步 1 MiB
- **0.26.0** 每秒吞吐序列——一个 8 秒平均描述不了「爆到 1.4G 再停」；
  对端窗口换算成 Mbps；修掉「wmem 不够」这条在 sndbuf 已顶到 wmem_max 时的错误建议
- **0.25.0** 诊断改为每秒采样，并交代每条连接为什么没入选
- **0.24.0** 自证：apply 完回读比对，不一致就逐行打出来
- **0.23.0** 端口速率不再变成单流限速（拆成 `LINK_MBPS` / `SHAPER_MBPS` /
  `FLOW_MAXRATE_MBPS`）；撤回 `tcp_frto=0` 和 `tcp_no_metrics_save=1`
